# Plan: cloud build (no Mac, no Apple account yet)

From [SPEC-cloud-build.md](../../SPEC-cloud-build.md), approved 2026-11-14.

## Approach

- Everything iOS runs on GitHub's `macos-15` runners (free, public repo). The Linux core job stays as it is.
- The Xcode project is generated by XcodeGen from `project.yml`; the generated `.xcodeproj` is not committed.
- Builds are for the iOS Simulator with signing turned off (`CODE_SIGNING_ALLOWED=NO`), since there is no Apple account yet.
- Screenshots come from a UI test that opens the app in Arabic and in English. The workflow pulls them out of the test results, stores them on a `screenshots` branch, and comments them on the pull request so they open in the GitHub app on a phone.
- TestFlight is task 5 and stays blocked until Meshari has the account.

## Order and risks

1. App skeleton and the macOS build come first, because everything else depends on the project generating and building on the runner. Risk: runner Xcode version; we pin it in the workflow.
2. App tests next, so the app target has a test gate like the core.
3. Screenshots after that. Risk: extracting attachments from `.xcresult` changes between Xcode versions; we pin Xcode and check the command in CI.
4. Widget extension and App Group last of the unsigned work, since they only need to build for now.

## Checkpoints

- After task 1: the macOS job is green on the PR.
- After task 3: Meshari sees Arabic and English screenshots on a PR from his phone and says they're fine.
